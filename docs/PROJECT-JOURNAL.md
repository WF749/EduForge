## 1. 一句话与边界

**EduForge · 教铸**：面向 K-12 教师的**本地优先**多模态备课工作台。
Vue3 + FastAPI 单体，后端托管前端构建产物，教案 / PPT / 动画 / 游戏四路生成，
外加**教学合规质检（R1–R8）**与**数据出校合规（L1–L5）**两道独立关卡。

边界（刻意不做的事）：
- 不做多用户 / 权限体系（后端无鉴权，前端只做入口分层 + 危险操作二次确认）
- 不上云：默认本地 / 内网模型，数据不出校
- 不追求"模型更强"，追求"同样的模型下，产物更可靠、过程可追溯"

### 2.3 关键设计取舍（为什么这么做）

| 决策 | 理由 |
|---|---|
| **LLM 调用统一走网关 / 服务层** | 项目历史上出现过 4 条调用链路，只在网关插桩会让生成功能完全裸奔 |
| **合规闸门"只报告、不阻断"** | 质检失败不能丢掉教师已经生成的内容 |
| **成品版本链只有一套机制** | 曾经有两套（content_version_manager 已成死代码），必须收敛 |
| **对话有两条路，不许合并** | 备课对话（带课程语境）vs 通用问答；合并会让"提问"被当成"需求没说全" |
| **前端路径改动必跑契约测试** | `/chat/dialogue` 曾写错，两边各自都对、合起来静默失效 |
| **颜色只用 `--wb-*` token** | 组件里写死 `rgba(255,255,255,.07)` 在深色主题下会变成白雾 |
| **同步重活必须丢线程池** | 见 §3 记录 A2，一次生成会把整个事件循环占住 |
| **写进成品的文本必须过出口闸门** | 见 §3 记录 A5，`str(dict)` 会把 repr 印进 Word/PPT |

## 3. 问题与修复记录

> 格式：`现象 → 根因 → 解法 → 验证 → 教训`

### A · 生成产物质量

#### A1. 教案导出：Letter 纸 + 字号层级混乱（09-19）
- **现象**：Word 默认是 Letter 不是 A4；渲染里到处 `str(v)`，模型把一条目标写成 `{"具体目标": …}` 就把 Python repr 印进 Word。
- **根因**：python-docx 默认纸张是 Letter；模型返回的字段形状不固定，渲染层却直接 `str()`。
- **解法**：显式设 A4；统一字号层级；新增"把结构读成人话"的清洗函数。
- **验证**：新增 `smoke_lesson_docx.py`（35 项）。
- **教训**：排版问题界面上看不出来，教师下载打印才发现，而且坏得很安静。

#### A2. 生成期间整站卡死（10-16）
- **现象**：工作台在跑生成任务时，「我的备课」「设置」永远转骨架屏，没有任何说明。
- **根因（后端架构缺陷）**：除 `teaching.py` 外，重活（LLM 调用、向量检索）全在 `async def` 里**同步**执行，把 uvicorn 的**事件循环整个占住**。生成期间后端无法响应任何其他请求。
- **解法**：
  1. 所有重调用改 `await run_in_threadpool(...)`（lesson_plan / courseware / ppt 三个域 + `api_routes` 里 7 处 `query_kb`）；
  2. `_generate_ppt_task` / `_generate_modified_ppt_task` 由 `async def` 改成 **`def`**——Starlette 对同步函数自动丢线程池，对 async 则在事件循环里跑；
  3. 前端同时补"信息"：StateBlock 新增慢加载态（>4s 提示、>25s 给重试），顶栏加常驻「正在生成 X」指示。
- **验证**：注入"慢 0.5s"假生成函数 + ticker 统计事件循环调度次数 —— 修复后 2 秒内调度 **32 次**（修复前 **0 次**）。988 项全绿。
- **教训**：**只给骨架屏等于没有信息**——教师无法区分"在加载"和"卡死了"。

#### A3. PPT 全是白底黑字，且末尾两页是废话（10-19）
- **现象**：15 页全是母版占位符（每页 2 个形状）、4:3；末尾两页硬编码「选择题：关于X的核心概念」。
- **根因**：`_write_pptx` 用"填占位符"而非"绘制画布"；`_build_detailed_content` 无条件 append 两个模板页。
- **解法**：
  1. 画布改 **1280×720 像素网格**，建立母版三区（A 标题 0–120 / B 内容 120–660 / C 页脚 660–720 含 `NN / TOTAL` 页码）；
  2. **8 种版式库**（cover/toc/bullets/cards/compare/formula/emphasis/summary），按内容特征自动选、相邻页不重复；
  3. 公式页：从标题抽出 `X = Y` 作 30–40pt 主视觉；`F_浮`/`ρ_液`/`cm³` 用 run 的 `baseline` 排成真上下标；
  4. 收尾页：大纲已有练习/小结就不再追加，要补也从已生成的概念里提炼。
- **验证**：用原 PPT 真实文案重画，15 页、每页 3–23 个形状、下标 49 处生效、无 repr。
- **教训**：**"有颜色"不等于"有设计"**。真正拉开差距的是母版一致性 + 视觉锚点 + 版式多样性。

#### A4. Python repr 印进成品（10-19，最致命）
- **现象**：Word 单元格里 `1. {'具体目标': "能准确说出…"}`；PPT 要点里 `['控制变量法验证：…']`。
- **根因**：`_heal_literals` 的"解析不了就原样保留"——而模型输出的 repr **恰恰经常**因截断 / 引号 / 全角符号导致 `literal_eval` 失败，这条防线在最常见场景下失效。
- **解法**：新建 `services/text_render.py` 作为**唯一出口闸门**：
  1. `degrade_literal()`：解析失败时降级成人话，**绝不原样返回**；
  2. 括号**各端独立**剥离（截断的 repr 没有闭合括号，要求首尾成对就等于放弃）；
  3. `heal_lines()` **逐行**自愈（整串判定会因首行不是 `{`/`[` 而放弃）；
  4. 行首标记支持**多重**（`• • ['…']` 只剥一层会漏）。
  教案侧五个清洗方法转发过去（API 不变）。
- **验证**：新增 `smoke_text_render.py`（31 项，用例**全部取自真实事故现场**）。
- **教训**：⚠️ **`smoke_lesson_docx.py` 35 项全绿却完全没抓到这个 bug**——它用的是干净假数据，真实模型返回的形状一条都没覆盖。**测试必须用事故原文驱动。**

#### A5. 自动排版溢出（10-19，三个实测 bug）
1. **下标贪婪吃中文**：`F_浮线性变化` 的「浮线性变化」整串变下标 → 中文下标只取 **1 字**（英文/数字可到 4 字符）。
2. **pt/px 混算**：行高按 `size×1.6` 估，但字号是 **pt**、可用空间是 **px**（差 1.33 倍）→ 34pt 文字直接排出色块边界。改为 `size×2.15`。
3. **卡片高度写死 400px**：配一句短话就是下半页 70% 空白 → 改为按内容行数自适应。
- **解法补充**：新增 `_fit_size()` / `_clip()` 文本预算层，按可用空间选字号，放不下就截断加"…"。
- **教训**：python-pptx 不会自动收缩文字，也没有渲染反馈——**自动排版必须留余量，字号宁小勿大**。

#### A6. PIL 渲染中文导致进程 segfault（10-19，最危险的一个）
- **现象**：调用配图逻辑时整个 Python 进程**直接崩溃**（退出码 139），后端若是同步调用会整个挂掉。
- **根因**：逐步探测定位到 —— PIL 的 import、几何绘制、字体加载都正常，
  **唯独 `draw.text()` 渲染中文时 segfault**。segfault 不是异常，`try/except` **拦不住**。
- **诱因**：`services/image_service.py` 的装饰图会在图上渲染中文主题文字。
- **解法**：配图兜底改用 `services/image_gen.py::decorative()` ——
  **只画几何形状，不画任何文字**；不再调用 `image_service.get_slide_image()`。
- **验证**：原本一跑就崩的脚本现在正常出图。
- **教训**：⚠️ 崩溃时 **stdout 缓冲区不刷新**，看不到任何 print，很容易误判成"卡住"。
  排查这类问题必须每步 `print(..., flush=True)` 或用 `-u`。

#### A7. 接入 AI 生图（通义万相 wanx，10-19）
- **需求**：课件要有真实示意图。
- **接口依据**（阿里云百炼官方文档 2026-10 核实，**不凭记忆**）：
  - 提交：`POST https://dashscope.aliyuncs.com/api/v1/services/aigc/text2image/image-synthesis`
    头 `X-DashScope-Async: enable` + `Authorization: Bearer <key>`
    体 `{"model":"wanx2.1-t2i-turbo","input":{"prompt":"…"},"parameters":{"size":"1024*1024","n":1}}`
  - 轮询：`GET https://dashscope.aliyuncs.com/api/v1/tasks/{task_id}`，`output.task_status` 到 `SUCCEEDED` 取 `results[0].url`
  - **图片 URL 仅 24 小时有效 → 必须下载到本地**
  - 限制：免费额度 500 张/90 天，**QPS 2、并发 1**（故强制串行 + 最小间隔）
- **解法**：新建 `services/image_gen.py`，做成**三级降级链**：
  `AI 生图 → 本地几何装饰图 → 无图`。任何一步失败都继续，**绝不阻塞 PPT 生成**。
  模式开关 `EDUFORGE_PPT_IMAGE_MODE`（`ai` / `deco` / `off`），张数上限 `EDUFORGE_PPT_IMAGE_MAX`（默认 2）。
- **关键设计**：配图必须跟着**最终版式**走 —— 新增 `layouts_for()` 让渲染与配图共用同一份
  版式决策，否则会给"根本不插图"的版式（卡片/目录页）白白生图（按张计费）。
- **验证**：新增测试 8 项（**注入假生图，不真调接口烧额度**），覆盖 off / 成功 / 失败降级 / 抛异常不中断。
- **教训**：顺带收紧了版式判据 —— 之前把含 `×`/`ρ` 的页都算成公式页，结果 7 页连着同一版式，
  **比只用一种版式更单调**。现在只认"标题里有等号"这一个强信号。

#### A8. 主题与学科矛盾时静默生成（10-19，整份产物作废）
- **现象**：工作台「教学主题=细胞的结构」+「学科=数学」，系统不提示，直接生成
  一份"用数学读懂生命、统计核糖体数量"的生物课件。**排版再好也是废的。**
- **根因**：主题与学科是两个独立字段，任何一层都**没有一致性校验**。
- **解法**：新增 `frontend/src/utils/subjectGuard.js`（九门学科强特征词表），
  在 `LessonBar` 字段区顶部提示，并给「改为「生物」」一键按钮。
- **关键取舍**：**只提醒、不自动改**——跨学科课（数学×生物）本身合法，
  系统替教师改等于把合法的跨学科课掰成单科。
- **验证**：`scripts/smoke_subject_guard.mjs` 25 项，两个方向都钉死
  （该提醒必须提醒；**不该提醒的一个都不能报**，否则提示变噪音）。
- **教训**：⚠️ 我写测试时先自相矛盾了一次——同一输入既要求提醒又要求不提醒。
  真跨学科应定义为"主题同时命中两科强词"。

#### A9. python-pptx 没有动画能力（硬限制）
- **实测**（0.6.23）：`Slide` 公开 API 只有 `background / element / ... / shapes`，
  **无 animation / timing / transition**。
- **结论**：要做 PPT 动画只能拿 `slide.element` 手写 OOXML 的 `<p:timing>` 树，
  无官方支持、易错、需逐版本验证。**不能对外承诺"支持 PPT 动画"**。
- **替代**：① 用"逐步出现的多页"代替动画（最稳）；② 生成 HTML 动画
  （项目已有 canvas 动画生成器）；③ 手写 timing 树（不建议）。

#### A10. 教材知识库：从本地教材 PDF 自动建索引（10-19）
- **需求**：有教材参考教材，没教材就从知识点出发。
- **⚠️ 版权红线（先说）**：教材 PDF 版权归出版社（GitHub 上的
  `TapXWorld/ChinaTextbook` 自身就是 **All Rights Reserved**）。
  **教材 PDF 绝不入库**，只放 `textbooks_local/`（已进 `.gitignore`）或仓库外。
  索引里**只存目录结构**（章/节/页码），不存任何正文。
- **实现**：
  - `scripts/build_textbook_index.py`：扫描 PDF → 自动识别目录页 → 提取章/节 → 输出 JSON。
  - `services/textbook_index.py`：`lookup(学科, 年级, 课题)` → `{章, 节, 页码}` 或 **None**。
- **实测三套教材三种目录格式**（解析器都要认）：
  | 教材 | 格式 |
  |---|---|
  | 初中物理 | `第一章 机械运动 9` / `第1节 长度和时间的测量 10` |
  | 小学数学 | `1 位置与方向（一）` + **换行页码**，且**没有"章"层**（平铺条目） |
  | 高中数学 | `第六章 平面向量及其应用…………１`（全角数字 + 点线引导） |
  - 两个坑：① 跨行页码要先合并回标题行；② 小学数学没有章层，
    压成"1 章 N 节"会丢单元边界 → 加 `flat_mode`。
  - 扫描版文字层有**重复行**（"主 编"/"主主 编编"），需去重。
- **最关键的行为**：查不到**返回 None**，并在提示里明写"不要编造教材章节号"。
  实测「浮力」在物理八年级**下册**，本地只有上册 → 正确降级，不编"第10章"。
- **验证**：`scripts/smoke_textbook_index.py` **16 项**（定位准 + 不编造 + 索引无正文）。

#### A11. 课件契约 + 校验器 + 渲染器（10-19，让"能上课"可验收）
- **背景**：此前生成链路的终点是"一堆文本 + 一个版式"，于是出现
  「选择题：关于X的核心概念」这种凑页数的页 —— 它没有教学功能，也没有规则拦住它。
- **关键区分**：`_write_pptx` 的 8 种是**排版版式**（这页长什么样）；
  这里定义 12 种是**教学功能页**（这页在课上干什么）。
- **落地三件**：
  1. `services/lesson_deck.py`：12 种页面类型的字段契约 + 校验 + **5 维量规打分**
     （总分 ≥20 且无维度 <3 才合格，对齐标准文档）
  2. `services/deck_renderer.py`：按教学功能页渲染，学段字号规范
     （正文 小学28/初中26/高中24 pt），**主动写教师备注**（标准第 6 条）
  3. `knowledge_base/golden_decks/decks.json`：12 份黄金样例入库，
     既是内置打样也是 LLM 的 few-shot
- **校验器抓到的真问题**：
  - 占位符硬门槛（`请填写/待补充/XXX/PXX/此处插入…`）
  - 闭环缺失（标准：六段齐全是**合格线**，不是扣分项 —— 缺一段直接不合格）
  - 练习有题无答案
  - 活动只有名字没有 steps
- **自己踩的两个坑**：
  1. 占位符规则误杀英语题里的 `____`（合法填空线）→ 区分"题干"与"其他字段"，
     且长下划线（`_{6,}`）才算留白待填。**误报会让校验失去信任。**
  2. 扫描时把整个 `items` 排除了 → 占位符漏检。排除"字段"和"放行某类字符"是两件事。
- **教师备注**：12 份黄金样例本身是 **0/14 页有备注**，我们渲染后是 **14/14**。
  没有教师自写备注时按页面类型给一条**可用的兜底话术**，而不是留空。
- **验证**：`smoke_lesson_deck.py` 23 项（黄金样例全合格 + 4 类反例全拦住 + 不误杀）。

#### A13. 契约模式接入 /ppt/generate（10-19，最后一环）
- **改法**：`_generate_ppt_task` 最前面加 `_try_deck_mode`：
  先查内置黄金样例（零成本）→ 未命中则 LLM 按契约生成 → 校验通过才渲染交付。
  结果落成与原有链路同构（ppt_data.json / task.result / files.pptx / compliance），
  所以 `/preview` `/download` `/status` 三个接口**一行都不用改**。
- **最重要的一条**：**任何失败都静默降级**回原有流程 ——
  生成异常、校验未通过（实测 11 分那次）、渲染失败、开关关闭，一律降级。
  宁可少一条新链路，也不能让教师等半天什么都拿不到。
- **刻意不动**原有流程的一行逻辑（只在最前面加一个可放弃的分支），
  开关 `EDUFORGE_PPT_DECK_MODE` 可整体关闭。
- **验证**：`smoke_deck_generator.py` 扩到 **33 项**，新增接入层降级 12 项
  （学段推断 / 结果结构 / 带溯源 / 不合格降级 / 异常静默降级 / 开关可关）。

#### A12. 提交时把 24 个临时 PNG 误入库（10-19）
- **现象**：`git add -A` 把 `generated_images/*.png`（测试生成的装饰图）一起提交了。
- **根因**：只给 `textbooks_local/` 加了 .gitignore，忘了运行时生成的图片目录。
- **解法**：补 .gitignore + `rm -f` 删文件 + `git commit --amend` 修正最后一次提交
  （**未推送**，本地 amend 安全）。
- **教训**：提交前必须扫一遍 `*.png / *.log / *.pdf`，
  `git add -A` 会吞掉所有没被忽略的文件。

### B · 采样参数（temperature）

#### B1. 教师被迫理解技术参数，且一个值覆盖所有用途（10-16）
- **现象**：全局只有一个 temperature（默认 0.7），既用于"抽取结构化字段"（应当极确定）也用于"课堂活动构思"（需要发散）。
- **解法**：新建 `core/sampling.py`，策略表集中维护（意图提取 0.1 / 知识问答 0.2 / 教案正文 0.4 / 活动构思 0.7 / 代码生成 0.2 / 兜底 0.4），按**用途 + 阶段**解析。
- **优先级**：调用点明确指定（planner/fix/verifier 内部约定）**>** 手动值 **>** 用途策略 **>** 兜底。
- **关键修复**：全项目两处 `cfg.get("temperature") or 0.7` 改掉——`or` 会把**合法的 0** 悄悄换成 0.7。

#### B2. 模型能力：三态而非布尔（10-16 / 10-19）
- **设计**：`supported` / `unsupported` / `unknown`。**unknown 保持兼容模式照常发送**，绝不因为"没验证过"就砍掉参数。
- **能力清单**在 `providers.py::KNOWN_TEMPERATURE_MODELS`，只登记本项目实际用的 13 款，**不编造未知模型能力**。
- **开发者可手动覆盖**（`temperatureOverride`）：专门给 local / demo / 自建网关——它们的模型名查不到清单，必然是 unknown。

#### B3. `/api/llm/config` 返回 500（10-19）
- **现象**：接口报 `TypeError`。
- **根因**：`model_supports_temperature()` 只收 2 个参数，接口层却传了 3 个（override）。
- **解法**：补上 override 参数并透传；新增一致性测试（"能力判定"与"是否发送"必须同参数同结论）。
- **教训**：⚠️ **`smoke_api_contract.py` 只查路由路径、不查响应内容**，接口内部报错它照样全绿。改了接口处理逻辑必须另外真跑一次接口。

#### B4. 切换能力覆盖后界面状态滞后（10-19）
- **现象**：选了「不支持 temperature」，界面仍显示"已验证支持"，要保存刷新后才对。
- **解法**：本地 override 立刻参与 `samplingRange` 计算。

### C · 前端与主题

#### C1. 深色主题下大面积露白块（10-16 / 10-19，两次）
- **现象**（10-16）：设置页「开发者选项」折叠头是一整块白。
- **现象**（10-19 全站扫描）：**所有默认 el-button 是纯白块**，同类还有分页按钮、数字输入加减按钮、单选按钮、代码块复制按钮、`danger.is-plain` 的浅红底。
- **根因**：Element Plus 这些组件用 `fill-color-blank`（纯白）打底，**不吃 `--wb-*` 语义 token**。
- **解法**：在 `main.scss` 集中加 Element Plus 对齐段；顺便把禁用态文字对比从 **1.63** 提到可读。
- **验证**：Edge 无头 + CDP 程序化扫描 **20 个「页面 × 主题」组合**（含两个真实预览页），全部 0 白块 / 0 黑块 / 0 低对比 / 0 溢出。
- **教训**：主题 token 只覆盖自己写的组件，第三方组件要单独对齐。

#### C2. 前端首次访问白屏 / 构建中断风险
- **红线**：**绝不能直接 `npm run build`**——`vite build` 会先清空 `frontend/dist`，而 dist 是后端生产托管目录。
- **做法**：构建到临时目录 → 备份 → 替换 → 校验资源齐全。本机 `mv` 常被系统拒绝，需准备 `cp -r` 回退。

### D · 工程治理（历史遗留，仍是当前约束）

| 问题 | 现状 |
|---|---|
| `git rm` 删单文件被沙箱守卫误扩成清空整个父目录 | 禁用 `git rm`；用 `rm -f` + `git add -A` |
| 提交信息含反引号/叹号被 bash 历史展开吃掉 | 用 `git commit -F <文件>` |

| 主题键 `eduforge.theme` 存**裸字符串**不是 JSON | 设置主题时用 `'light'`/`'dark'`/`'system'` |

## 4. 仍然开放的坑（按优先级）

1. **PPT 没有真图片** —— `services/image_service.py` 只有 `generate_image_queries()`（生成搜索关键词），**没有生图能力**。要真图需新接图像生成 API（供应商 + 额度 + 新依赖）。
2. **教案占位符** —— `教材PXX页`、`________`、`（请根据实际情况补充）`；PPT 的 `教师：XXX｜2024学年`。需要在 prompt 里明确禁止。
3. **教案无标题层级** —— 全是 `Normal` 样式，长文档没有导航感。
4. **公式仍是纯文本**（`F_浮`）在教案侧未处理（PPT 侧已修）。
5. **emoji 字形** —— `▶ ✘ ✔ ⚠️` 在部分 Word 字体下变方框。
6. **自动排版没有视觉反馈** —— 只有保守估算，没有 lint / VLM 检测兜底。
7. **仓库里还有过程性文档** —— `00-项目诊断与企业级重构规划.md`、`POSITIONING*.md`、`性能优化说明.md` 等，按 AGENTS.md 红线 5 不该入库。
