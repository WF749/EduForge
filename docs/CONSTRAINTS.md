# 硬约束清单

> 本文是 [`AGENTS.md`](../AGENTS.md) 第 2 节「8 条红线」的展开版：每条都写清**为什么**，
> 以便 AI 与人类在边界处自行判断，而不是死记规则。
> 分类：**A 前端可访问性 / B 数据合规 / C 教学合规 / D 模型调用 / E 依赖与架构 / F 文档与仓库**。

---

## A. 前端可访问性（最高优先级）

### A1. 禁止直接 `npm run build`

- **原因**：`vite build` 会先 `emptyOutDir` 清空 `frontend/dist`，而 **dist 是后端生产托管目录**
  （`backend/app/main.py` 的 `_FRONTEND_DIST = frontend/dist`，SPA fallback 从这里读 index.html）。
  构建一旦中断，用户打开站点就是白屏，且**无法通过回滚 git 修复**（dist 不在版本控制里）。
- **正确流程**（永不清空在用的 dist）：
  ```bash
  cd frontend
  npx vite build --outDir .build-new --emptyOutDir   # 1. 构建到临时目录
  grep -rl "本次改动的关键字" .build-new/assets/*.js   # 2. 确认新代码真的进了包
  mv dist dist_old && mv .build-new dist              # 3. 重命名替换（目录始终存在）
  # 4. 起后端验证：/ 返回 index.html，/assets/xxx.js 返回 200
  # 5. 确认无误后再分批删除 dist_old
  ```
- **仅验证能否编译**：`npx vite build --outDir .verify-dist --emptyOutDir`，跑完删掉。

### A2. 不要提交也不要删除 `frontend/dist`

它在 `.gitignore` 中，是运行期产物，但**是线上前端的唯一来源**。清理磁盘空间时跳过它。

### A3. 后端路由改动不得破坏 SPA fallback

新增 `/api/*` 之外的路由时，确认根路径与静态资源仍能被正确托管。

### A4. 工作台是默认入口，旧功能页只下线导航、不下线路由

`/` 渲染 `WorkbenchView`；`/chat`、`/courseware`、`/animation`、`/game`、`/preview/:taskId`
**仍然可访问**，只是不出现在顶部导航里。
- **原因**：工作台的 PPT 流程要跳 `/preview/:taskId`，导航改了但路由删掉会直接断链；
  工作台出问题时也需要能退回旧页面继续干活。
- 改动工作台时，先确认 `/preview/:taskId` 这条链路还能用。

### A5. 一节课的上下文只存一份

主题 / 学科 / 年级 / 课时 / 难度 / 参考资料 / 面板级选项（PPT 主题色、动画时长、游戏类型）
统一放 `frontend/src/store/lesson.js`。
- **原因**：四类产物共用这些参数。"一键批量生成"和"进面板单独生成"必须产出同样的东西，
  否则两套参数各存一份必然漂移。
- 注意**动画时长 ≠ 课时时长**：课时默认 45 分钟，动画默认 5 分钟，不要把课时塞进动画时长。

### A6. 成品版本只有一套机制：`artifact_versions`

教案 / 动画 / 游戏 / PPT 的版本历史统一走 `backend/app/services/artifact_versions.py`，
主键是 `(lesson_id, kind)`；对外接口只有 `/api/artifacts/{versions,content,revert}`。

- **原因**：仓库里曾经同时存在三套互不相通的"版本"——`content_version_manager`（零调用，
  且每次修改都把全文回灌知识库）、PPT 的 `task_dir/versions.json`（绑死后台任务目录）、
  `/lesson-plan/modify`（只在响应里返回，不落盘）。结果是谁都能"改"，但没人能"回退"。
  三套已在 2026-09-18 收敛为一套（PPT 的 `versions.json` 暂留，待后台任务链路稳定后迁移）。
- **不许再开第 N 套**。要支持新的成品类型，往 `artifact_versions.KINDS` 里登记即可。
- **回退必须是非破坏性的**：不删任何历史，把目标版本复制成新版本并在 `note` 写明来源。
  这样"回退错了"还能再回退回来，历史也不会被截断。
- **存版本失败不能让生成/修改失败**：内容已经在手里，丢版本只是少了回退能力；
  把生成接口打回失败等于白跑一次模型（失败原因挂 `version_error`）。
- **不暴露"独立存版本"的写接口**：版本必须和"这次改动做了什么"绑定，
  单独开写接口容易出现"内容改了但没记版本"的空洞。

### A7. 前端调后端接口：路径必须能在后端路由表里查到

前端一律用 `${BASE()}/xxx`（`BASE()` = `resolveApiBaseURL()`，自带 `/api`）或指向本项目
后端的 axios 实例 + 相对路径。**不要**凭印象写路径，也不要新造一个不带 `/api` 的入口。

- **原因**：路径写错不报错，只静默降级。`lessonChat.js` 曾写成 `/chat/dialogue`
  （真实路由是 `/api/chat/analyze`），POST 落到 SPA 兜底路由上返回 405，
  前端 catch 住只显示"对话服务没响应"，整条澄清链路废掉而页面一切照常 —— 没人会发现。
- `scripts/smoke_api_contract.py` 会扫出前端所有接口路径，逐个去后端路由表比对，
  改任何一处路径后必须跑它。
- 后端新增路由时不用改这个测试；但**删路由/改前缀**必须跑，它会把前端还在用的旧路径报出来。

### A8. 对话有两条路：提问走问答，要东西走动作

工作台对话必须区分两类话，且**两类走不同的后端接口**：

| 教师说的是什么 | 判定的地方 | 走的接口 | 得到什么 |
|---|---|---|---|
| 「什么是三角函数」「学生总搞混 k 和 b，怎么讲」 | `looksLikeQuestion()` | `POST /api/lesson-chat/ask`（流式） | 真的答案 |
| 「生成一份浮力教案」「导入太抽象，换成煮饺子的例子」 | `routeUserMessage()` 的规则 | 各生成/修改接口 | 动作 + 进度卡片 |
| 「帮我搞个能讲浮力的东西」（想做点什么但没说清） | 兜底 | `POST /api/chat/analyze`（状态机） | 澄清 / 确认 |

- **原因**：这两类话曾经共用一条状态机。状态机只会问"你还缺哪些字段"，
  于是**所有提问都被当成"需求没说全"**：教师问「什么是三角函数」，
  拿回来的是「请问您想了解什么主题的知识」；再问一句，只剩一句
  「我理解了你的需求。你可以直接说要生成什么」——对话成了套了层壳的菜单。
  （根因之一：`dialogue_manager._handle_initial_state` 的 `execute` 分支
  **不返回 `message` 字段**，前端拿不到任何话可说，只能掉进兜底文案。）
- **兜底必须是回答**：状态机给不出可执行结果（没有 message、接口异常）时，
  前端一律退回答问，**不允许**再出现"你直接说要生成什么"这种把锅推给用户的话。
- **`looksLikeQuestion` 词表宁窄勿宽**：漏判的代价是多一次澄清往返（兜底仍会回答），
  误判的代价是把一句修改指令送进问答、绕掉真正的动作 ——
  "换成煮饺子的**例子**"里那个"例子"就曾是这样一个误判源，已从词表移除。
- **问答的课程语境走 system，不拼进用户消息**：语境是长期背景，
  拼进 message 会让模型以为教师刚说了那一长串。`llm_client._messages_from_payload`
  与 `_messages_multimodal` 共用 `_system_prefix()`，两条链路取到同一份 system。
- 测试：`node scripts/smoke_chat_action.mjs`（分流规则）、
  `scripts/smoke_lesson_tutor.py`（语境与行为准则）。

## B. 数据合规

### B1. 新增 LLM 调用路径必须接入出校插桩

- **原因**：项目历史上出现过 **4 条独立 LLM 调用路径**，早期只在网关检查，
  导致教案/PPT/动画/游戏生成**完全绕过**合规检查。
- **现状**：已在 3 个收口点插桩（网关 / `llm_client` / `services/llm`），
  `scripts/smoke_safety.py` 含**静态回归校验**防止新增链路漏接。
- **要求**：新增任何调用大模型的入口，先确认它落在已有收口点之内，并跑 `smoke_safety.py`。

### B2. 默认策略是 `warn`，它不阻断数据外发

- `EDUFORGE_SAFETY_MODE` 默认 `warn`：定级照做、响应头照写、前端徽标照显示，
  **但数据原样发往目标模型**。
- **实测**：L4 数据（成绩名单）→ `action=warn`、`allowed=true`、`egress=true`。
- 处理真实学生数据前必须 `EDUFORGE_SAFETY_MODE=enforce`，或切到 local provider（Ollama / 内网模型）。
- **不要**把默认值悄悄改成 `off`。

### B3. 敏感识别必须保持"本地规则"，不得改用模型识别

- **悖论**：用模型识别敏感信息，等于为了防泄漏先泄漏一次（识别本身要把原文送进模型）。
- 代价是精度有限，因此高置信规则（身份证/手机号/邮箱/考号）才可用于阻断，
  结构规则（成绩表/名单/试题段）默认只告警。

### B4. 响应头 `X-Data-*` 只放类型，绝不放原文

`X-Data-Findings` 只允许出现命中类型与数量。

## C. 教学合规

### C1. 闸门永远"只报告、不阻断"

`run_compliance_gate()` 的任何异常都必须吞掉并返回 `enabled=False`。
**绝不允许**因为质检失败而丢弃生成结果——这是本项目最重要的可靠性约定。
开关：`EDUFORGE_COMPLIANCE_GATE=0`。

### C2. 规则保持"纯规则、离线"

R1–R8 不调用大模型、零额度消耗，才能在每次生成后无成本跑一遍。
**不要**把某条规则改成"调模型判断"。

### C3. 新增规则必须同步补反例测试

历史教训：物理题里的「重力：10N」「答案：3」与"姓名:成绩"长得一模一样，早期版本误判为隐私泄露，
同一份 PPT 的质检得分从 67 掉到 92 才修好。
- 非人名标签黑名单 + 单位/百分号排除 **还不够**，
  正则必须加 `(?<![一-龥])` **词首锚定**——否则引擎会从第二个字起匹配绕过黑名单。

### C4. R7/R8 采用"调用方传结构化文本才检查"

不扫描全文猜"哪段是教学目标"（"培养/了解/提高"到处都是，必误报）。
教案接口单独传 `objectives_text` 与 `assessment_text`。**不要**改回全文扫描。

## D. 模型调用

### D1. 输出上限不得低于 8192

`resolve_max_tokens()` 统一解析，默认 8192（可用 `EDUFORGE_LLM_MAX_TOKENS` 覆盖）。
- **原因**：4096 会把 12 模块的教案截断（`finish_reason='length'`）→ JSON 不完整 → 解析出全空模块，
  表现为"生成成功但内容全空"。`scripts/smoke_lesson_plan.py` 已钉死此值。
- moonshot 因 8k 上下文单独用 `resolve_max_tokens(4096)`，不要统一改。

### D2. 模型调用失败必须显式标记，绝不静默兜底

`degraded=True` 要让前端能提示"非真实生成"。**禁止**用模板内容假装成功——
这是本项目明确划定的"与企业级玩具的分界线"。

落地方式（2026-09-18 补齐，此前文档写了但流式链路没做到）：
- 真实模型失败后**默认不降级**到 DemoProvider。降级开关是
  `EDUFORGE_LLM_FALLBACK_TO_DEMO`，默认关闭；只有显式置为 `true` 才允许。
- 允许降级时，**必须先产出 `[演示模式兜底]` 声明、再产出模板内容**。
  顺序反了等于没说：用户先读到模板、再读到"这是模板"。
- 用户显式选择 `demo` 作为 provider 时，它失败就是真失败，**不允许"兜底成它自己"**。
- 流式链路抛异常会截断 SSE，因此失败一律产出提示文本（`_failure_notice`），
  与合规拦截的 `_guard_notice` 保持同一手法。
- 回归测试：`scripts/smoke_llm_service.py`。这类问题不报错、不进日志，只能靠测试发现。

### D3. 长耗时任务放后台 + 轮询

PPT 生成走后台任务，报告写 `task.result["compliance"]`，随 `/api/ppt/status` 带出。**不要**在请求线程里跑长任务。

### D4. 不给"后端其实做不到"的选项

前端提供的每个选项，后端必须真的按它做事。
- **原因**：本项目把"选项可选但没有实效""上传成功但 AI 没用上"列为一类缺陷专门修过。
  新增控件前先确认后端分支存在且真实生效，否则宁可不放这个控件。
- 已知反例（**不要**再开放）：`LessonPlanGenerator.export_lesson_plan` 对 `export_format="pdf"`
  的实现是"PDF暂时生成docx"，所以教案导出只暴露 docx。

## E. 依赖与架构

### E1. 依赖极简，优先"能内化进仓库推理"的技术

倾向可组合、API 稳定、模型训练集中表现好的技术。新增依赖前先确认现有代码能否覆盖；
确需新增，在提交信息里写理由。参考 [`docs/TECH-EVALUATION.md`](TECH-EVALUATION.md)。

### E2. 横切能力走统一入口

认证、连接器、遥测、配置等横切关注点，只通过**单一显式接口**进入各层，不要在业务代码里散落调用。
（现状：LLM Harness 已是统一入口，重试/超时/熔断/追踪/降级都在这一层。）

### E3. 边界处解析数据形状

在模块边界验证并解析输入（类型化模型），而不是让脏数据流进内部后再打补丁。

## F. 文档与仓库

### F1. 文档边界：什么该入库、什么不该

| 该入库 | 不该入库（已移出 8 份，勿重新加回） |
|---|---|
| README、架构、开发流程、约束、技术方案、API 说明 | 竞品分析与定位论证 |
| 决策记录、**执行计划**（含决策日志） | 求职/面试叙事材料 |
| 评测结果与指标 | 代码审查报告、排查过程记录 |
| 给 AI 看的规则文件（本文件、AGENTS.md） | 待办清单、工作日志、诊断方案 |

- 判断标准：**这份内容 6 个月后对新加入的人/AI 还有用吗？** 过程性结论转译成"规范"后才入库。

### F2. 知识必须留在仓库里

"AI 看不到的东西就不存在"——只存在于对话、聊天工具或人脑里的决策，等于不存在。
任何非显而易见的共识，都必须落成仓库里的 Markdown。

### F3. 提交与历史

- 不要 force push，不要重写历史（除非用户明确要求）。
- 提交信息写**为什么**，不只是做了什么。
- 提交前确认 `git status` 干净且不包含运行期产物。

### F4. 不要写真实内网地址

示例统一用 `192.168.1.100` 等保留私有地址。历史上有真实内网地址被写进代码与文档，已脱敏，**勿回退**。
