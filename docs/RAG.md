# 企业级 RAG 全链路

面向 K-12 备课场景的检索增强生成链路：**中文向量 + 中文关键词 + 重排序 + 拒答闸门 + 引用溯源**。

代码位于 `backend/app/rag/`，评测集 `evals/rag_eval_set.jsonl`（100 条），
评测入口 `scripts/rag_eval.py`（`make eval`）。

---

## 1. 链路

```
查询
 ├─ 向量通道   bge-small-zh-v1.5（本地，512 维）→ Chroma 余弦检索
 └─ 关键词通道 BM25（jieba 分词，缺失时自动降级字符二元组）
        ↓  RRF 融合（Reciprocal Rank Fusion, k=60）
     候选集（两通道并集 top-20）
        ↓  重排序（本地 bge-reranker-base → 百炼 API → 不重排）
          只重排融合分最高的前 8 条（见 §3.3 延迟实测）
     阈值判定 → 低于阈值**直接拒答**，不把无关上下文交给模型
        ↓
     命中片段 + 引用溯源（来源文件 / 标题路径 / 原文）
```

| 模块 | 文件 | 职责 |
|---|---|---|
| 分块 | `chunker.py` | 结构感知切分，保留 Markdown 标题路径 |
| 向量 | `embeddings.py` | 本地 bge 中文模型，加载失败**明确降级** |
| 关键词 | `bm25.py` | 纯 Python BM25，零第三方依赖 |
| 重排序 | `rerank.py` | 本地 bge-reranker-base → 百炼 API → 不重排 |
| 检索 | `retriever.py` | 双通道融合、阈值拒答、引用溯源 |
| 评测 | `evalset.py` | 指标计算与报告 |

## 2. 关键设计决策（都有实测依据，不是照搬最佳实践）

### 2.1 分块必须保留标题路径

按固定字数硬切会把知识点拦腰截断。这里按 Markdown 标题分节，
再把标题前缀拼进 chunk 文本一并向量化：

```
【初中数学一元二次方程教学知识库 > 知识点 > 二、解法】
1. 直接开平方法 ...
```

**实测影响**：rerank 阶段若传去掉标题的原文（而非带标题的文本），
可答题「Python中如何定义函数」会被误拒——两个环节看到的文本必须一致。

### 2.2 融合用 RRF，不用加权求和

向量分（余弦）与 BM25 分（无上界）量纲不同，加权求和需要先归一化，
而归一化系数会随语料漂移。RRF 只用**排名**，天然量纲无关。

### 2.3 阈值必须用绝对分，不能用批内归一化分

**踩过的坑**：BM25 分按当前候选集的最大值归一化后，
当所有候选都是噪声时，最差的那个也会被拉到 1.0。
结果「太阳系有几颗行星」因"行/星"二字命中酒店礼貌用语，
拿到 0.98 分被判定为强命中而放行。

修正后只用三种**绝对分**判定：向量余弦、rerank 分、BM25 原始分。

### 2.4 拒答必须对全部候选取最优值，不能只看第一名

RRF 融合后的第一名可能是 BM25 独有候选（向量通道没召回它，`vector_score=0`）。
若只看第一名，正确答案明明排在第 2、3 位也会被拒。
**实测这个 bug 让可答题误拒率达到 6.7%。**

### 2.5 单通道（向量或 BM25）都分不开相关/无关 —— rerank 不是可选项

100 条评测集上的实测分布：

| 通道 | 可答（90 条）最低分 | 应拒答（10 条）最高分 | 结论 |
|---|---|---|---|
| 向量余弦（bge-small-zh） | 0.36 | **0.49** | 重叠 |
| BM25 原始分 | 3.02 | **6.59** | 完全重叠 |

两簇都重叠 —— **任何向量阈值或 BM25 阈值都不可能同时压住误拒和漏拒**。
这不是模型选得不好，而是要点式短文本本身难用无监督打分区分
（"量子力学的不确定性原理"对每个短片段都"有点像"）。
这正是必须做 rerank 的原因，不是为了堆技术栈。

### 2.6 阈值与 rerank 后端强绑定，换后端必须重标

**这是本项目踩得最狠的一个坑。** 阈值不是超参，是模型输出的分布分位，
换一个 rerank 模型，分位就全变了。

本地 bge-reranker-base 输出的是 logit（约 -12~+12），用它直接和
百炼 API（0~1）共用阈值毫无意义。因此统一做 sigmoid 压到 0~1 ——
**sigmoid 是单调的，不影响排序，只统一阈值的量纲。**

实测两个后端的分布完全不同：

| 后端 | 可答最低分 | 应拒答最高分 | 合适阈值 |
|---|---|---|---|
| 百炼 qwen3-rerank | 0.421 | 0.365 | ~0.39 |
| 本地 bge-reranker-base（sigmoid 后） | 0.588 | 0.536 | **0.55** |

沿用为云端标定的 0.39 时，**10 条该拒的查询一条都没拦住（漏拒率 1.000）**。

### 2.7 阈值取"距悬崖最远"的点，不是取紧贴边界的点

sigmoid 会让分数在两端饱和，本地模型的阈值扫描呈现**悬崖式劣化**：

| 阈值 | Recall@1 | 误拒 | 漏拒 | 加权分 |
|---|---|---|---|---|
| 0.50 | 0.967 | 0.000 | **1.000** | -2.033 |
| **0.55** | **0.967** | **0.022** | **0.000** | **0.945** |
| 0.60 | 0.922 | 0.067 | 0.000 | 0.856 |
| 0.70 | 0.800 | 0.200 | 0.000 | 0.600 |
| 0.75 | **0.000** | 1.000 | 0.000 | -1.000 |

0.75 处全部拒答 —— 因为 sigmoid 饱和后绝大多数分数挤在 0.50~0.67。
因此 0.55 的价值不只是"当前最优"，更是**距两侧悬崖都最远**：
向下 0.05 会开始漏拒，向上 0.20 才会全面误拒。

评测集只有 10 条拒答样本，样本量小，**必须留足余量**。
扫描命令：`python scripts/rag_eval.py --sweep`（漏拒按 3 倍权重惩罚，
因为漏拒会让模型拿着无关上下文编造，代价远大于误拒）。

### 2.8 阈值扫描必须"检索一次、离线重扫"

老实现是每个阈值重跑一遍全量检索。向量/BM25 通道只要 13ms，重来无妨；
但本地 cross-encoder 单次 ~800ms，100 条 × 9 档 = 12 分钟，慢到没人愿意跑。

而阈值**不影响候选集与排序，只影响最终是否拒答**。因此 `RAGEvaluator.collect()`
把拒答闸门关掉（阈值设 -1）跑一遍，留档每条的 `best_rerank / best_vector / best_bm25`
与命中结果；`evaluate_at()` 在这些留档分数上做纯计算，扫描变成零检索成本。

## 3. 评测结果

评测集：100 条（可答 90 / 应拒答 10），覆盖 6 篇种子文档 + 10 条语料外问题。
下列数字均为 `python scripts/rag_eval.py` 实测输出，非估算。

### 3.1 完整链路（本地 bge-reranker-base 重排，阈值 0.55）

| 指标 | 值 |
|---|---|
| Recall@1 | **0.967** |
| Recall@3 / @5 | 0.978 / 0.978 |
| MRR@5 | **0.972** |
| TermHit@1 | 0.933 |
| 拒答准确率 | **0.980** |
| 误拒率 | 0.022（2 条） |
| 漏拒率 | **0.000** |
| 延迟 p50 | 672ms |

### 3.2 降级链路（rerank 不可用，纯向量 + BM25）

| 指标 | 值 |
|---|---|
| Recall@1 | 0.944 |
| MRR@5 | 0.944 |
| TermHit@1 | 0.867 |
| 拒答准确率 | 0.940 |
| 误拒率 | 0.056（5 条） |
| 漏拒率 | **0.100**（1 条该拒的放行了） |
| 延迟 p50 | 13ms |

**结论**：本地重排在准确率上全面优于不重排（误拒 5 条 → 2 条，漏拒 1 条 → 0 条），
代价是延迟从 13ms 升到 672ms。对"备课"这种非实时场景，这个交换是划算的；
若部署在实时对话里，可用 `enable_rerank=False` 关掉。

### 3.3 延迟：cross-encoder 是唯一重计算环节，必须限流

实测（16 核 CPU，候选片段平均 98 字）：

| 配置 | 端到端 p50 |
|---|---|
| 20 条候选全量重排 | 2073ms |
| **前 8 条重排（当前默认）** | **773ms** |
| 不重排 | 13ms |

cross-encoder 开销 = O(候选数 × token²)。我们最终只返回 top-5，
把 20 条全送进模型是纯粹的浪费，因此只重排融合分最高的前 8 条，
未重排的候选保持 RRF 顺序排在后面（**分数记为 `None` 而非 0** ——
用 0 填充会污染拒答判定里的 `max()`）。

> 试过 torch 动态量化求加速，但在当前 torch/transformers 组合下
> `quantize_dynamic` 会破坏 XLM-RoBERTa 的前向（`AttributeError`）。
> **正确性优先，未启用。** 后续可改用 optimum + ONNX Runtime 重测。

### 3.4 已知失效模式（不掩饰）

剩余 3 条未达标，根因相同且**与阈值无关**：

| 查询 | 知识库中的正确内容 | 实际 |
|---|---|---|
| 集合有什么用途 | `4. 集合(Set)：去重、交集、并集` | 误拒 |
| with语句有什么作用 | `3. with语句和上下文管理器` | 误拒 |
| 字典用什么结构存储数据 | `3. 字典(Dict)：键值对操作` | 排到 `sample_knowledge` |

三条的正确答案都**埋在编号列表的第 3、4 项**。分块器把整个
"列表/元组/字典/集合"列表切成一个 chunk，cross-encoder 看到的内容
70% 与查询无关，分数被稀释到阈值以下。

**这是分块粒度问题，不是阈值问题** —— 再怎么调阈值也救不回来。
正确修法是让分块器对超长编号/项目列表按条目二次切分（每条保留标题路径前缀）。
本次未改动：涉及重新索引与全量回归，风险高于收益，且当前 96.7% 已可用。
已记入 §7 已知缺陷清单。

> **过拟合提示**：阈值是在这 100 条上调出来的，其中拒答样本只有 10 条。
> 上述数字应理解为"当前评测集上的拟合优度"，换一份语料需要重新标定
> （`--sweep` 会自动给出建议阈值）。

### 指标为什么不完全照搬 RAGAS

RAGAS 的 `faithfulness` / `answer_relevancy` 需要额外调用大模型逐条打分，
100 条就是 100+ 次 LLM 调用，慢、贵，且分数受评委模型影响。这里拆两层：

- **第一层（默认，零成本、可 CI 化）**：Recall@k、MRR@5、TermHit@1、拒答准确率、延迟
- **第二层（可选 `--with-llm`）**：Faithfulness、AnswerRelevancy（要花钱，默认关闭）

## 4. 降级矩阵

每一级降级都会**如实上报**，绝不假装成功：

| 能力 | 降级条件 | 表现 |
|---|---|---|
| 向量通道 | embedding 模型缺失/加载失败 | 仅 BM25，结果标记 `degraded` |
| 中文分词 | jieba 未安装 | 字符二元组（零依赖，精度略降） |
| 重排序 | 本地模型未下载 + 百炼不可用 | 保留 RRF 顺序，`rerank_backend="none"` |
| 检索不到 | 低于阈值 | **拒答**，返回明确原因与诊断分数 |

重排序默认走**本地 cross-encoder**，不是因为效果更好，而是因为
重排序会把「用户查询 + 知识库原文」一起送出，走云端等于把校内资料外传，
与项目"数据不出校"的定位直接矛盾。附带好处是不受账户余额影响 ——
实测百炼账户欠费时 API 直接返回 400，核心检索链路不该挂在账户余额上。

状态查询：`GET /api/rag/status`（含 `rerank.local_ready`，可自证本地通道是否就绪）

## 5. 使用

```bash
# 首次：下载中文 embedding 模型（95MB，检索必需）
python scripts/fetch_embedding_model.py

# 推荐：再下载本地 rerank 模型（1.0GB，拒答准确率的保障，见 §3.2）
python scripts/fetch_embedding_model.py --model rerank

# 检查就绪状态
python scripts/fetch_embedding_model.py --check --model all

# 重建索引
python scripts/rag_eval.py --reindex --no-rerank

# 评测（含 rerank）
python scripts/rag_eval.py

# 评测（离线、零成本）
python scripts/rag_eval.py --no-rerank

# 阈值扫描（检索一次 + 离线重扫，零额外检索成本）
python scripts/rag_eval.py --sweep

# 换 rerank 后端后必须重标阈值，可先用扫描确认分位：
python scripts/rag_eval.py --min-rerank 0.55
```

接口：

```
GET    /api/rag/status              索引与两通道状态
POST   /api/rag/search              混合检索（返回引用溯源）
GET    /api/rag/documents           文档列表
POST   /api/rag/documents           索引文档
DELETE /api/rag/documents/{id}      删除文档
POST   /api/rag/reindex             用 knowledge_base/ 全量重建
```

## 6. 两套知识库已统一

改造前项目里有两套互不相通的知识库，同一个文件在"对话"搜得到、
在"生成课件"搜不到：

1. `app/knowledge_store.py` —— 对话页与文件上传，字符重合打分
2. `app/services/rag_service.py` —— 课件/教案生成，Chroma + 英文 embedding

现在统一到 `app/rag/retriever.py`：

- JSON 仍是**上传内容的持久化真源**（列表、删除、版本管理依赖它）
- 写入时同步建混合索引；删除时同步移除
- 查询走混合检索，失败自动退回字符重合打分
- 对 `app.rag` 的导入全部**函数内惰性导入**，避免启动即加载模型

注意 `clear_all()` 只清理 `origin=upload` 的文档，不会误删种子知识库。

## 7. 已知缺陷清单（下一步该改什么）

按收益排序，都是本次实测发现的、有明确定位的问题：

| # | 问题 | 根因 | 建议修法 | 影响 |
|---|---|---|---|---|
| 1 | 编号列表中第 3、4 项的知识点检索不到 | 分块粒度：整个列表切成一个 chunk，目标项被稀释 | 分块器对超长编号/项目列表按条目二次切分，每条保留标题路径 | Recall@1 3.3% |
| 2 | 换 rerank 后端后阈值失效 | 阈值是输出分布的分位，非超参 | 已缓解（`--sweep` 零成本重标）；长期应在 `stats()` 里暴露当前后端并校验阈值匹配 | 换后端时会静默劣化 |
| 3 | 应拒答样本仅 10 条 | 评测集规模 | 扩到 50+ 条拒答样本，并做交叉验证 | 阈值稳健性存疑 |
| 4 | cross-encoder 占 99% 延迟 | CPU 推理 278M 模型 | optimum + ONNX Runtime 量化（torch 动态量化在当前版本下会破坏模型，已排除） | p95 985ms |
| 5 | `sample_knowledge.md` 是示例占位文件，含大量元描述文本 | 种子语料未清理 | 真实部署时应替换；保留它可测试系统在噪声语料下的表现 | 干扰排序 |

## 8. 模型下载的两个坑（国内网络）

1. `huggingface.co` 直连经常 502，需用社区镜像 `hf-mirror.com`
2. **huggingface_hub 经镜像下载会静默产生 0 字节文件** ——
   `modules.json`、`config_sentence_transformers.json`、`model.safetensors` 都出现过，
   随后报 `JSONDecodeError: Expecting value` 或 `SafetensorError: header too small`
   （错误信息极具误导性，看起来像模型坏了，实际是网络层截断）

`scripts/fetch_embedding_model.py` 改为直连 HTTP 逐文件下载 + `Content-Length` 校验
+ 大小下限检测 + 失败重试，并强制使用 `parents[2]` 定位 `backend/models_cache`
（层级写错会找不到本地模型而回退到网络下载）。
